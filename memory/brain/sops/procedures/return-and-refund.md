# Procedure: Return and refund
A cross-department procedure. It never overrides company rules, governance/ or the approval tiers. A person approves anything live.

## Purpose
Handle returns fairly and within the law, with the owner deciding every refund.

## Trigger
A customer asks to return an item or wants a refund.

## Roles
- customer care
- operations
- finance
- the owner decides

## Steps
1. Record the request against the order ID. Ask which of three it is: changed mind, faulty or not as described, or damaged in transit.
2. Check the platform's own return rules and your policy (catalogue/support/facts.yml). UK consumers usually have a 14-day right to cancel distance sales, and faulty goods have separate rights. Check the current rules with Trading Standards guidance before you rely on this.
3. Draft the reply from the returns template. Do not promise a refund: the owner decides.
4. Owner approves the outcome. If a return is needed, give clear instructions that do not ask for card details.
5. On receipt, check the item, then the owner approves the refund. Record the refund on the order (watch.py order update --refund).
6. Tell finance. Note any product or supplier problem for sales and operations.

## Records
- The request, decision, refund and reason

## Escalate to the owner
- Every refund
- A pattern of the same fault
- A safety issue

## Done when
- [ ] Customer told
- [ ] Refund recorded
- [ ] Cause noted
